# The Instrument Experiment — Unified Frontier-Bets Rig (Cowork Handoff)

*One corpus, one sweep, three pre-registered hypotheses: does a deliberately weak model measure road quality, is the ladder floor a dual certificate, and does adversarial certification actually certify?*

Status: pre-build. Builds ON TOP of the existing Dot Maps repo (harness Phase 1–3 complete, 42 tests passing, ollama traveler validated, probe command working, attack reports written for maps 1–3). This spec adds an experiment layer; it changes no harness semantics.

Companion docs: `dot_maps_v0.1_build_spec.md` (the product), `grounded_convergence_spec.md` (the earlier research program — superseded in priority by this rig, which tests the claims the novelty audit ranked highest).

---

## 0. The three bets, stated as one sentence each (from the novelty audit)

- **B1 — Weak-probe-as-instrument (top-ranked):** a deliberately weak model, held fixed, is a measurement instrument whose convergence behavior grades the quality of the map (the road/spec), not the model. Unclaimed in the literature; the field runs this relationship in the opposite direction only (difficulty calibration for curricula).
- **B2 — Ladder floor as dual certificate:** the cheapest model that reliably completes a map is simultaneously a cost certificate for the buyer and a quality score for the map. FrugalGPT computes the floor and discards it; nobody re-uses it as a quality stamp.
- **B3 — Adversarial malicious-compliance certification:** an attack stage that constructs pass-all-dots-fail-the-goal outputs, used as a pre-deployment GATE, measurably reduces the Goodhart gap of certified maps. SpecBench measures the gap; nobody gates on it.

Why one rig suffices: all three are readouts of the same sweep — (map variants of known quality) × (models on a ladder) × (attack stage), with the existing probe/scoreboard as the data logger.

## 1. The scarce resource: a corpus with KNOWN quality variation

You cannot correlate convergence with road quality unless quality is known. With 4 base maps, quality ground truth must be manufactured — the same planted-classes move as E3 in the earlier spec: because WE construct the degradations, the quality ordering is ground truth by construction.

### 1.1 Corpus generator (`dotmaps corpus`) — the main new build item

Input: a certified base map. Output: a family of variants, each tagged with its degradation recipe and a derived **quality tier**.

Degradation operators (each parameterized, composable, deterministic under a seed):
- `sparsify(p)` — remove fraction p of non-terminal dots (road density ↓). Keep the terminal/outcome dot always.
- `blunt(dot_ids)` — replace a verifier with a strictly weaker check (e.g., "file exists" instead of "file matches schema"; "HTTP response received" instead of "200 + content assertions"). Each blunted verifier must still be a real check — never a tautology (tautologies are a separate tier, see below).
- `scramble(k)` — rewire k dependency edges to plausible-but-wrong orderings (DAG validity preserved).
- `defog()` — delete fog declarations (undeclared judgment residue).
- `tautologize(dot_ids)` — replace verifiers with always-pass stubs. This is the known-worst tier and the direct Goodhart probe: a map that "passes" while checking nothing.

Enrichment operators (for the upper tiers):
- `densify()` — split coarse dots into finer intermediate dots with real verifiers (use the base map's existing verifier _lib; human-review each generated verifier before it enters the corpus — verifier synthesis is explicitly NOT being tested here, so keep this step human-gated and small).

Tier assignment (ordinal, by construction):
- T0 = tautologized (worst) · T1 = heavily degraded (sparsify ≥0.5 or ≥2 operators) · T2 = lightly degraded (one mild operator) · T3 = base certified map · T4 = densified (best)

Corpus size target: 3 base maps (smoke, map-2 content-migration, map-3 health-recert; map 1 joins when Cloudflare MCP lands) × ~8–12 variants each ≈ **25–35 variants**. Each variant is a full map repo (manifest + verifiers + Dockerfile), generated by script into `corpus/`, with `variant.json` recording {base, operators, seed, tier}.

Integrity checks on the generator itself (tests required): every variant's DAG is valid; every non-tautology verifier actually runs and can fail (feed it a deliberately broken workspace — it must exit 1); tier labels reproducible from recipe.

### 1.2 Honest-limitation note (write into the paper later, not a blocker)
Constructed degradation = planted ground truth. Legitimate for the first result; natural variation (real customer maps over time) is the follow-up dataset. State this in any writeup.

## 2. The sweep (`dotmaps sweep`)

For every corpus variant × every ladder rung: run N fresh probe runs, full harness semantics unchanged (sovereign verifier, full-manifest re-verification, budget caps).

- **Ladder rungs (v1):** qwen2.5-coder:3b, qwen2.5-coder:7b (the validated instrument), qwen2.5-coder:14b if the old Mac tolerates it, + one frontier rung via API for the ceiling reference (small N, it's a reference point not a subject).
- **N per cell:** 5 fresh runs minimum (matches existing probe); 10 for the 7B instrument rung on all variants (B1 needs the tightest intervals on that rung).
- **Budget per run:** inherit each base map's budget; do NOT raise budgets for degraded variants (budget exhaustion on a bad road is signal, not noise).
- **Logged per run (mostly already in the scoreboard — verify completeness, add what's missing):** all_green?; cycles-to-green; wall time; total tokens (prompt+completion) and $ if API; dots eaten per cycle (progress curve); regressions triggered; budget-death point if red; per-dot attempt counts (which dots consumed retries).
- Output: one tidy `sweep_results.jsonl`, one row per run, joinable to `variant.json`.

Estimated compute: ~30 variants × 3 local rungs × 5 runs ≈ 450 runs. At the observed ~1–7 min/run on local models, that's roughly 1–3 days of unattended machine time on the Ollama box. Run it in tranches; the JSONL is append-only so tranches compose.

## 3. Pre-registered hypotheses, metrics, and kill criteria

Freeze this section BEFORE the sweep runs. No metric additions after first analysis (that is how false positives get manufactured — same discipline as the earlier spec).

### H1 — Weak-probe-as-instrument (B1, the career bet)
- **Claim:** the 7B instrument's convergence metrics rank-order the corpus by quality tier.
- **Primary metric:** Spearman rank correlation ρ between tier (T0–T4) and instrument score, where instrument score v1 = pass rate (Wilson lower bound, per novelty-audit stats guidance) with cycles-to-green as tiebreaker. Secondary (exploratory, declared now): run-to-run variance; progress-curve slope; budget-death timing.
- **Success:** ρ > 0.7 (the audit's own benchmark) with 95% CI excluding 0.4.
- **Kill:** ρ < 0.4 → the instrument thesis fails in this regime; fall back to fleet-based difficulty labeling (Terminal-Bench style) for the product, and say so plainly.
- **Confound control:** T0 (tautologized) maps will trivially pass — the instrument reads them as EXCELLENT roads. This is not a bug in H1; it is the boundary between B1 and B3: the probe measures traversability, the attack stage measures meaningfulness. A road of fake tollbooths is very traversable. Report T0 separately; H1's correlation is computed over T1–T4, and T0's inversion is itself a reportable finding (the probe alone CANNOT be the certificate — it needs B3 as its partner).

### H2 — Ladder floor as dual certificate (B2)
- **Claim:** the floor (cheapest rung achieving ≥4/5, Wilson-adjusted) moves monotonically with tier: better roads certify down to smaller models.
- **Primary metric:** monotonic trend of floor vs tier (Jonckheere–Terpstra or simple ordinal regression; with 3–4 rungs, report the contingency table honestly rather than overclaiming).
- **Success:** monotone non-increasing floor from T1→T4 in ≥2 of 3 base-map families.
- **Kill:** floor flat across tiers → the floor measures model capability only, not road quality; it remains a cost certificate (still useful for the product) but the dual-certificate claim dies.

### H3 — Adversarial certification certifies (B3)
- **Claim:** attack-hardened maps have a smaller Goodhart gap than their pre-hardening versions on HELD-OUT attacks.
- **Design:** for each base map, take (i) the pre-hardening version (reconstruct from git history — the B1 source-rewrite era exists in the repo's history) and (ii) the current hardened version. Generate a fresh attack set with a DIFFERENT frontier model than wrote the original attack reports (attacker diversity guards against attacker-specific overfitting). Each attack = an attempted artifact/workspace that passes all dots while failing the true goal (true goal judged by the terminal outcome dot of the UNdegraded map + human spot-check).
- **Primary metric:** held-out attack success rate, hardened vs pre-hardened. Add the verify-the-verifier axis: mutation testing on verifiers (inject faults into workspaces; % of mutants each verifier suite kills), target >80% kill per the audit.
- **Success:** attack success rate drops by ≥50% relative AND mutation kill rate for hardened suites >80%.
- **Kill:** hardened ≈ pre-hardened on held-out attacks → hardening overfits to the attacker that produced it; certification-as-gate is theater in this form. Report it — that is a real (and publishable-as-negative) result about rubric hardening.

### The composite readout (product synthesis)
If H1+H2 survive: define the **stamp** = {instrument score (7B, Wilson), floor, attack report verdict + mutation kill rate}. One JSON block per map, produced by `dotmaps certify`, replacing the current ad-hoc trio. This becomes Phase-3's gate in the product spec and the label on every sold map. If only some hypotheses survive, the stamp contains only the surviving components — the experiment decides the product's certification stack, which is the whole point.

## 4. Build items (delta on the existing repo — nothing else)

1. `dotmaps corpus` — generator + operators + integrity tests (§1.1). **The main work. ~2–3 evenings.**
2. `dotmaps ladder` — loop existing probe over a model list, emit `ladder_stats.json`. (~1 evening; mostly plumbing around what exists.)
3. Probe stats upgrade — Wilson lower bounds in probe/ladder outputs (small; use the standard closed form, no dependency needed).
4. `dotmaps sweep` — orchestrate §2, resumable via the JSONL (an outer loop over corpus × rungs calling existing machinery). (~1 evening.)
5. Scoreboard completeness pass — confirm per-run logging covers §2's field list; add missing fields. (hours)
6. Held-out attack harness for H3 — attacker prompt + workspace-injection runner + mutation-testing script for verifiers. (~2 evenings; reuse attack-report tooling.)
7. `analysis/` notebook — loads sweep_results + variant tags, computes H1–H3 metrics exactly as pre-registered, renders the three headline figures: (F1) tier vs instrument score scatter with ρ; (F2) floor-by-tier table; (F3) attack success pre/post hardening + kill rates.

Explicitly OUT of scope (the audit's own guardrail — at most one Stage-3 frontier bet, later, not now): verifier synthesis, automatic fog-drawing, feedback-to-manifest credit assignment, IRT floor prediction, compositional certification. Humans stay in those loops. Do not let corpus enrichment quietly become a verifier-synthesis project.

## 5. Execution order — SEQUENTIAL, with an early kill

**Stage 0 — the ambush pilot (~20 runs, one afternoon, run this before building anything beyond the corpus operators).**
One base-map family (map-2 content-migration — already probe-certified 5/5, so T3 behavior is known). Four variants only: one T1 (sparsify 0.5 + blunt), one T2 (single mild operator), T3 (the base), one T4 (densified). Skip T0 for the pilot (its inversion is already predicted). One rung: the 7B instrument. N=5 each → 20 runs, a few hours unattended.
**Decision rule (pre-registered):** compute pass rate + cycles-to-green per variant. If T1 and T3/T4 are not clearly separated (Wilson intervals overlapping AND cycles-to-green indistinguishable), H1 is dead-on-arrival in this regime — STOP, do not build the sweep, report the early kill, fall back to fleet-difficulty labeling for the product. If the extremes separate cleanly, the instrument has a pulse: proceed, and the full sweep's job becomes resolving the middle tiers and the correlation strength, which is what actually needs the N.
This is standard sequential testing: the full grid exists to measure ρ precisely, not to discover whether the effect exists at all. Discovery costs 20 runs; precision costs 450.

**Then, only if Stage 0 passes:**
1. Items 3+5 (stats + logging) → 2. Item 1 full corpus across families → 3. Item 4 sweep in tranches → 4. Item 6 attacks while sweep runs unattended → 5. Item 7 analysis, hypotheses judged against §3 verbatim → 6. If stamps survive: wire `dotmaps certify` into the product's Phase 3 and update the product spec.

## 6. Restatement for future-you

You are testing whether your measurement apparatus is real: whether a weak model reads road quality (H1), whether the floor is a quality stamp and not just a price tag (H2), and whether the attack gate actually gates (H3). The corpus is planted ground truth — the same move as E3 — and every hypothesis has a pre-registered kill. Whatever survives BECOMES the product's certification stack; whatever dies gets reported as dead. Either way the product ships with a stamp you can defend, and the surviving claims are the paper. The T0 finding is already predictable and already interesting: traversability and meaningfulness are different axes, and it takes both the probe and the adversary to certify a map. That sentence might be the abstract.
