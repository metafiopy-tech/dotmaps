§1 · LIVE

The instrument, running

One frozen weak agent. Three maps of unknown quality. The agent attempts each map repeatedly; its convergence rate — with a Wilson score interval — is the grade. When the interval's lower bound clears the pre-registered threshold θ = 0.70, the map is certified. When the upper bound falls below θ after n ≥ 50 trials, the map fails — and the negative is published, not buried. The agent never changes. Only the map is on trial.

Bench · frozen agent w-0 · θ = 0.70 · pre-registered
observed rate 95% Wilson interval θ threshold replay tape
What's simulated here: each map has a hidden traversal probability standing in for real predicate-map quality; trials are draws against it. In the real instrument, a trial is a full sandboxed run of the frozen agent against the map's predicates, and the replay tape is a verbatim, watchable record a counterparty can audit. The statistics — Wilson intervals, thresholds, certify/fail logic — are exactly what runs in v0.
§2 · CLAIM

The inversion

The literature uses weak models as the thing to be improved, supervised, or scaled past. Dot Maps inverts the direction of measurement: the weak model is the fixed instrument, and the environment — the predicate map — is what gets graded.

Literature direction

environment [fixed]
  ↓ shapes
weak model [measured, improved]

Weak-to-strong generalization, harness engineering, curriculum design: hold the world steady, lift the agent.

Dot Maps direction

weak model [fixed]
  ↓ probes
map [measured, certified]

Freeze the agent, read its convergence as a grade of the map. Sovereign verifiers issue the certificate; the replay is the proof.

Why adversarial, not cooperative

Harness engineering builds for the organization that trusts its own harness. Dot Maps builds for the counterparty who doesn't: frozen rules, critic pipelines, cheating detection, and a watchable replay any third party can verify. The cooperative frame asks "did our agent do well?" The adversarial frame asks "can you prove it to someone with no reason to believe you?"

The confound, stated up front

A fixed weak model's convergence might measure how legible a map is to that particular model rather than the map's intrinsic quality. These correlate but are not identical. The mitigation is in the design: expand to a grid of 3+ weak models × 3+ map sources, pre-registered. If the convergence ranking of maps is stable across different weak instruments, single-model legibility is ruled out as the sole explanation. This is the first limitation in the paper, not a footnote.

§3 · PAPER

The writeup — 8 pages, workshop format

1 · Introduction

One paragraph of thesis context: when generation is cheap, the scarce load-bearing function is the mechanism that decides what's real. The field is converging on this independently, so the thesis carries no moat — the instrument is the moat. The paper is about the instrument.

2 · Method

  • Predicate maps — structured, certifiable descriptions of a workflow as verifiable predicates.
  • Sovereign verifiers — independent verifiers issue certificates; no self-grading.
  • Frozen rules — the cheap agent and its rule set are pinned before any run.
  • Replay as trust certificate — a watchable record replaces "trust me."

3 · Pre-registration

Thresholds and kill criteria published verbatim before execution. Certification: interval lower bound ≥ θ. Failure: upper bound < θ at n ≥ minimum. Negatives are results, not embarrassments.

4 · Experiments

The v0 result plus the expanded grid: 3+ weak models × 3+ map sources, at least two task domains not constructed by the author. Client-derived workflows enter as case studies only — uncontrolled samples can't be pre-registered, so they support external validity without carrying core claims.

  • v0 result (Run 005): frontier learner (claude-sonnet-5), fresh API calls, zero session context, answer key withheld — banked 4 primitives, every one a real discriminating check; honestly fogged ~20 false hypotheses; grew a map that cleared the readout with zero circular checks (first ever); probe-certified 5/5; total cost $0.50. Pre-registered v0 signal MET: an agent grew a certifiable map with no task description and no oracle.

Certification now carries Wilson intervals (that map: [0.57, 1.00]) and re-certifies on any version change.

§4 · PROTOCOL

How to run the instrument

  1. Write the map

    Decompose the workflow into verifiable predicates — each one a check a machine can pass or fail, no judgment calls. The map is the artifact under test.

  2. Freeze the instrument

    Pin the weak model (exact version), its rule set, and its prompt scaffold. From this point, touching the agent invalidates the run.

  3. Pre-register

    Publish θ, minimum n, and kill criteria before the first trial. What would count as failure is written down while you still don't know the answer.

  4. Run the grid

    The frozen agent attempts the map repeatedly, sandboxed. Every trial produces a replay tape. Convergence accumulates; Wilson intervals narrow.

  5. Read the verdict

    Lower bound clears θ → the sovereign verifier issues a certificate bound to the replay. Upper bound falls below θ → the map fails, and the negative ships with the same visibility as a win.

  6. Hand over the certificate

    The consumer of the map gets the predicate list, the certificate, and the replay. They don't have to trust you — they can watch.

§5 · SANDBOX

Agents consuming Dot Maps: the sandbox upgrade

The same instrument that grades maps for humans upgrades a sandbox for agents. Today's sandboxes answer one question: did the code run? A Dot-Maps-equipped sandbox answers a stronger one: can this workflow be certifiably traversed — and here's the tape. Three integration surfaces:

A · The map bundle (context surface)

Ships like an AGENTS.md — a context bundle the agent reads before touching the workflow. Predicates, frozen rules, current certificate status. The agent doesn't discover the environment; it's handed the certified geometry of it.

// dotmap.json — consumed by any agent entering the sandbox
{
  "map_id": "sheets-booking-flow.v3",
  "predicates": [
    { "id": "P1", "check": "auth.jwt_valid",        "verifier": "sv-auth" },
    { "id": "P2", "check": "sheet.row_appended",     "verifier": "sv-data" },
    { "id": "P3", "check": "booking.confirmed_email", "verifier": "sv-io" }
  ],
  "frozen_rules": { "model": "w-0@pinned-sha", "max_steps": 40 },
  "certificate": {
    "status": "CERTIFIED", "theta": 0.70,
    "wilson_lower": 0.57, "wilson_upper": 1.00, "n": 5,
    "replay_uri": "replays/sheets-booking-flow.v3/",
    "issued_by": "sv-root", "preregistration": "prereg/2026-07-XX.md"
  }
}

B · The verifier endpoint (tool surface)

Exposed to agents as a tool (MCP-shaped): submit a traversal, get a graded verdict per predicate plus a replay pointer. The agent can't self-grade; the verdict comes from the sovereign verifier or it doesn't count.

// tool: dotmaps.verify_traversal
request:  { map_id, trajectory }
response: { verdict: "pass"|"fail",
            predicates: [{id, passed, evidence}],
            replay_uri, running_interval: [lo, hi] }

C · The promotion loop (lifecycle surface)

How an agent team uses the sandbox as a ladder rather than a cage:

  1. Admit

    New workflow enters as an uncertified map. Any agent may attempt it; nothing it produces is trusted downstream.

  2. Traverse

    The frozen weak instrument runs trials. Stronger agents may also run — their traversals generate candidate map revisions, never grades.

  3. Certify

    The interval clears θ under the weak instrument → certificate issued. The map is now a trusted rung: downstream agents may build on outputs that pass its predicates.

  4. Promote / demote

    Certified maps compose into larger maps. Any predicate drift (API change, environment shift) triggers re-verification; a failed re-check demotes the map and everything stacked on it — substrate-level honesty.

Why this is an upgrade and not a wrapper: the sandbox's trust boundary moves from "the code executed" to "a fixed, auditable instrument converged on it, within pre-registered bounds, on tape." That's the difference between a playground and an exam — and it's what lets one agent's work become another agent's ground truth.
§6 · FINDINGS

First contact: four findings from one real procedure

2026-07-30 — the translation layer met a real restaurant closing procedure, described by its owner. Four compile-test rounds: three published failures, one certification. Each failure produced a design finding now binding on the method. Full record: Case Study — Closing Procedure, Four Rounds.

F1 · Branch flattening

The compiler collapsed "if variance > $20, alert the manager" into a gate requiring variance ≤ $20 — a conditional flattened into a pass requirement. Consequence: predicate schema needs explicit branch semantics; compilers must preserve if/then structure.

F2 · The evidence ladder

Human-legible ≠ machine-verifiable. Physical-world steps bottom out in evidence artifacts (a named file, a written count) because verifiers can't enter the kitchen. Consequence: verification tiers are real — T1 judgment / T2 named observable state / T3 tamper-evident attestation — and the schema needs an evidence-binding predicate type.

F3 · The unfrozen verifier — promoted to method principle

An identical sentence graded CHECKABLE one round and NEEDS CLARITY the next: the compiler was re-rolling standards per invocation, demanding infinite attestation regress. The system violated its own thesis and its own loop caught it. Principle: every verifier in the pipeline — including the compiler — operates under frozen, pre-registered rules (fixed tier rubric, no escalation past the declared tier).

F4 · Length–quality conflation

A zero-ambiguity 7-predicate map failed at 0.35: whole-run conjunction scoring compounds per-step probability, so meticulous long maps score worse than sloppy short ones. Consequence: per-predicate certification — each predicate clears θ individually; the certificate is the conjunction of certified predicates. Map length must not masquerade as map quality. Open calibration note: post-fix pass rates ran hot; true per-predicate base rates are an empirical constant obtainable only from real sandboxed traversals.
