# The Receipt

*"The dream isn't a smarter model. It's a receipt."*
— from the vault, July 15, 2026, 2:25am

Every product in this space asks you to trust that the work was done
well. This one doesn't ask. A task you hand off comes back with proof
attached — proof the system generated by checking its own work against
the real world, not proof it wrote about itself afterward.

That's the whole bet: **trustworthy delegation**. Hand off a task where
the system itself proves the work was done correctly, so trust is never
required. The reliability profile of a scheduled job, applied to tasks
that were never written down as scheduled jobs before — because nobody
could write the check for them until now.

Two rules make the receipt real instead of decorative:

- **Every claim carries evidence.** A "done" that can't point at the
  exact check it passed isn't done, it's a guess with good manners.
- **Failure is loud and legible, never plausible-looking.** A broken
  thing looks broken. It never quietly renders as a green checkmark.

The visible proof of the bet, on every message: a small chip that says
either *nothing was called — it just replayed what she already knows,
free* or *she went and did real, newly-thought work with the model just
now, here's how much*. Nothing else shows you that number, message by
message, because nothing else is built around the claim that most of
what you ask for eventually gets cheap.

That's the whole reason to cancel the subscriptions underneath this: the
work that's already been proven runs free, forever, and the only thing
that ever costs anything again is the genuinely new ask.

**receipts:** the commitment above is quoted verbatim from the project's
own working notes, carried unedited into every build brief since.
